# 점검 규칙 전체 표 (상세 점검 결과 기준)

상세 점검 결과 화면에 표시될 수 있는 **모든 점검 규칙**을 정리한 표입니다.
규칙은 모두 DB 테이블 `inspection_rule`(`DownloadReviewRule`)에 `rule_type` + `config_json` 형태로 저장되며,
`gscert_review_core/engine.py`의 `rule_type`별 핸들러가 실행합니다.

- **기대값 공식**: 엔진이 "이래야 한다"라고 계산하는 값. `{...}`는 프로젝트 메타데이터/선행 규칙 산출 변수로 치환됩니다.
- **실제값 표시 방법**: 파일에서 추출하는 위치 + 결과 화면(`ecm_download_review.js`)에서 보여지는 방식.
- **세부 규칙 ID**: `1-1`, `1-2`, ..., `18-1` 형식의 상세 기준은 `main/docs/03_inspection_rule_manual.md`의 `세부 점검 규칙 ID` 절을 단일 원본으로 관리합니다.

> 치환 플레이스홀더: `{project_number}`(프로젝트번호) · `{product}`/`{제품명}` · `{company}`/`{회사명}` ·
> `{pl}` · `{wd}` · `{시작일}` · `{종료일}` · `{연도}` · `{신청일}` · `{계약일}` · `{인증위}` ·
> `{KEY}`(선행 규칙이 `raw_detail.variables`로 남긴 산출 변수)

---

## 0. 실제값이 화면에 표시되는 공통 방식

엔진은 규칙 1건당 `RuleEvaluation`을 반환하고, 다음 필드가 `inspection_result` 행으로 저장됩니다.

| 필드 | 의미 | 화면 표시 |
|---|---|---|
| `status` | `pass` / `fail` / `error` / `unsupported` | 정상/부적합/오류 배지 |
| `expected` | 기대값(여러 하위검사는 ` / ` 로 연결) | "기대값" 열 |
| `actual` | 실제값(여러 하위검사는 ` / ` 로 연결) | "실제값" 열 |
| `message` | 사용자 안내 문구 | 상세 메시지 |
| `file_name`/`file_path` | 대상 파일 | "파일명" 열 |
| `raw_detail_json.sub_checks` | `[{expected, actual, passed}]` 하위검사 목록 | 하위검사마다 **한 행씩** + 행별 정상/부적합 배지 |
| `raw_detail_json.artifacts` | PDF 1페이지 등 산출물 이미지 | 상세 결과의 파일/미리보기 링크 또는 HTML 다운로드 자료에 포함 |

`sub_checks`가 있으면 항목별로 행이 나뉘고 각 행에 배지가 붙습니다.
없으면 `expected`/`actual`을 ` / ` 로 분해해 보여주며, 전체 1개 배지를 사용합니다.

## 8. 규칙 간 산출 변수 흐름 (실행 순서 의존)

`sort_order` 순서로 실행되며, 선행 규칙이 `raw_detail.variables`로 남긴 값을 후속 규칙이 사용합니다.

```
시험성적서(95) ──► 결함차수, 1차, 2차, 시험성적서_세부사양표
   │                         │                    │
   │                         ▼                    ▼
   │                  결함리포트(100)          시험계획서(96) 세부사양 비교
   │                  ──► 잔여결함수, H, R
   │                         │
   ▼                         ▼
시험계획서 WD 등        테스트케이스(105) 잔여결함수 비교
                             │
                             ▼
                       점검표(110) C11=H, E11=R
                       ──► 측정항목별점수표
                             │
                             ▼
                       품질검사표(145) 점수표 비교
                       ──► 품질부특성측정값
                             │
                             ▼
                       품질평가보고서(150) 품질부특성 비교
```

> ⚠️ 변수 의존 때문에 `sort_order`를 바꾸면 선행 변수가 비어 후속 규칙이 실패할 수 있습니다.
> 시험성적서(95)·시험계획서(96)·테스트케이스(105)·품질검사표(145)는 의도적으로 순서를 조정한 값입니다.
