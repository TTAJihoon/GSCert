# 상담(consultation) 앱 접속 도메인 변경 안내 — 8787 개발팀 전달용

## 요약

지금까지 상담 지원 에이전트는 `https://210.96.71.194.nip.io/consultation/` 로 접속되어
왔고, 이 주소가 194 nginx를 거쳐 8787 앱(`https://210.96.71.67.nip.io:8787/`)을
리버스 프록시로 표시하는 구조였습니다.

전산팀이 정식 도메인 **`gsai.tta.or.kr`** 을 194 서버 IP(`210.96.71.194`)로 직접
DNS A레코드 등록을 완료했습니다. 앞으로는 IP 주소와 `nip.io` 임시 도메인을 모두 없애고
**`gsai.tta.or.kr` 하나로 통합**합니다.

- 기존: `https://210.96.71.194.nip.io/consultation/`
- 변경 후: **`https://gsai.tta.or.kr/consultation/`**

경로 접두어(`/consultation/`)는 **그대로 유지**됩니다. 194 쪽 nginx 리버스 프록시 구조
(브라우저에는 `gsai.tta.or.kr` 만 보이고, 실제 렌더링은 8787 앱)도 변경되지 않습니다.
바뀌는 것은 **호스트명(도메인) 딱 하나**입니다.

---

## 8787 팀에서 바꿔줘야 할 것

### 1. Google Cloud Console — OAuth 클라이언트 설정 ⭐ 필수

기존 값은 당장 지우지 말고, 아래를 **추가**해 주세요.

- **승인된 JavaScript 원본**: `https://gsai.tta.or.kr`
- **승인된 리디렉션 URI**: `https://gsai.tta.or.kr/consultation/auth/callback`
  (콜백 경로가 다르면 실제 경로로 알려주세요 — 그 경로 기준으로 다시 안내드리겠습니다)

### 2. 앱의 `auth.redirect_uri` (또는 동일 역할의) 설정값 변경 ⭐ 필수

8787 앱이 Google에 넘기는 `redirect_uri` 값을
`https://210.96.71.194.nip.io/consultation/auth/callback` →
**`https://gsai.tta.or.kr/consultation/auth/callback`** 으로 바꿔주세요.

194 nginx는 요청을 그대로(`Host` 헤더는 8787 자체 호스트로 재작성해서) 넘기기 때문에,
8787 앱이 스스로 이 값을 **고정값으로 알고 있어야** 합니다(요청 헤더에서 동적으로 유추하는
방식이 아니라면).

### 3. 쿠키 도메인 하드코딩 여부 재확인

세션 쿠키 도메인에 `210.96.71.194.nip.io` 같은 값이 하드코딩되어 있다면 이번에 함께
제거(미지정 = 현재 호스트 기본값)하거나 `gsai.tta.or.kr` 로 바꿔주세요.

### 4. 컷오버(전환) 시점 협의 ⭐ 중요

194 쪽에서 nginx를 반영하면, IP로 들어온 상담 접속은 곧바로 `gsai.tta.or.kr` 로
리다이렉트됩니다. 이 시점에 8787 쪽 리디렉션 URI가 아직 예전 값이면 Google 로그인이
`redirect_uri_mismatch` 오류로 실패합니다. 따라서:

- 1)·2)번 작업을 **194 쪽 전환과 같은 시점 또는 그 전에** 완료해 주시고,
- 언제 준비가 끝나는지 알려주시면 그 시점에 맞춰 194 쪽을 전환하겠습니다.
- (Google Console 설정 반영에 몇 분~수십 분 걸릴 수 있으니 여유를 두고 먼저 등록해두시는
  것을 권장합니다.)

전환 후 문제가 없는 것을 확인하면, 이전 nip.io 관련 등록 값은 서로 정리하겠습니다.

## 바뀌지 않는 것 (참고)

- 경로 접두어 `/consultation/` — 그대로.
- 194 → 8787 서버 간 내부 연결(`210.96.71.67.nip.io:8787`) — 이건 브라우저에는 보이지 않는
  194 nginx ↔ 8787 서버 간 내부 호출이라 이번 변경과 무관합니다. 그대로 둡니다.
- 리버스 프록시 방식 자체 — iframe이 아니라 194가 8787을 대신 호출하는 구조 그대로 유지.
