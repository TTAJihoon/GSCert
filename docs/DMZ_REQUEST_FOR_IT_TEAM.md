안녕하십니까.

GSCert 웹서비스(`gsai.tta.or.kr`) 담당자입니다.

직원이 외근·재택 중에도 GSCert를 사용할 수 있도록 외부 접속을 열고자 하며, 이를 위한 DMZ 서버 구성과 방화벽·DNS 설정을 요청드립니다.

## 1. 요청 배경

현재 GSCert 웹서비스는 사내에서만 접속이 가능합니다. 시험 담당자가 사외에서도 이력 조회·산출물 점검 등을 처리할 수 있도록 외부 접속 경로를 마련하려 합니다.

보안을 위해 앱 서버를 직접 노출하지 않고, **DMZ에 리버스 프록시 서버 1대를 두어 443 포트 하나만 내부로 통과시키는 구조**로 설계했습니다. DMZ 서버에는 애플리케이션·데이터베이스·계정 정보를 일절 두지 않습니다.

접속 대상은 **TTA 직원으로 한정**합니다. 외부 접속 시 회사 구글 계정(Google Workspace `tta.or.kr`) 로그인이 필수이며, 로그인하지 않으면 어떤 기능도 사용할 수 없습니다. 인증 시 Google이 발급하는 `hd`(hosted domain) 값을 서버에서 검증하여 회사 계정만 통과시킵니다. 사외 인원(인증 신청 기업 등)에게는 공개하지 않습니다.

## 2. 구성 개요

```
[외부 직원]                                 [사내 직원]
    |                                           |
    | 공개 DNS: gsai.tta.or.kr → DMZ 공인 IP     | 사내 DNS: gsai.tta.or.kr → 210.96.71.194
    v                                           |
[경계 WAF/IPS]                                  |
    v                                           |
[DMZ 서버 (신규, Linux)]                        |
  - nginx 리버스 프록시 전용                     |
  - 앱/DB/계정정보 없음                          |
    | 443 만                                     |
    v                                           v
[GSCert 앱 서버 210.96.71.194]  (기존, 변경 없음)
```

## 3. 요청 사항

### 3-1. DMZ 서버용 공인 IP 1개 배정

- 신규 서버 1대(Linux), 용도는 리버스 프록시 전용
- DMZ 세그먼트 배치 및 공인 IP 1개 배정을 요청드립니다
- 서버 자체는 저희가 준비·구축하겠습니다

### 3-2. DNS 분리 설정 (split-horizon)

`gsai.tta.or.kr` 하나의 이름이 접속 위치에 따라 다르게 해석되도록 설정을 요청드립니다.

| 해석 위치 | 대상 |
|---|---|
| 공개(외부) DNS | DMZ 서버 공인 IP |
| 사내 DNS | `210.96.71.194` (현재와 동일) |

**이렇게 요청드리는 이유**: 관리자 페이지와 사내 전용 API는 외부에 공개하지 않을 계획입니다. 사내 트래픽이 DMZ를 경유하지 않고 기존처럼 앱 서버로 직결되어야, 사내 담당자는 관리 기능을 계속 쓰면서 외부에는 노출되지 않는 구성이 성립합니다.

사용자 입장에서는 사내·사외 모두 같은 주소(`https://gsai.tta.or.kr`)를 쓰게 되어 안내가 단순해집니다.

### 3-3. 방화벽 정책

| # | 구간 | 프로토콜/포트 | 출발지 | 목적지 | 정책 |
|---|------|--------------|--------|--------|------|
| 1 | Internet → DMZ | TCP 443 | any | DMZ 공인 IP | **허용** (유일한 서비스 인바운드) |
| 2 | Internet → DMZ | TCP 80 | any | DMZ 공인 IP | **허용** (HTTPS 리다이렉트 전용) |
| 3 | DMZ → 내부 | TCP 443 | DMZ 서버 | `210.96.71.194` **단일 호스트** | **허용** |
| 4 | DMZ → 내부 | 그 외 전부 | DMZ 서버 | 내부 전체 | **차단** (5432, 445, 139, 3389, 5985, 8000, 22 포함) |
| 5 | 내부 → DMZ | 전부 | 내부 | DMZ 서버 | **차단** |
| 6 | DMZ → Internet | TCP 443 | DMZ 서버 | 인증서 갱신·OS 패치 대상 | **최소 허용**, 그 외 아웃바운드 차단 |

3번이 핵심입니다. DMZ 서버는 **앱 서버 한 대의 443 포트 외에는 내부 어디로도 접속할 수 없어야** 합니다. DMZ가 침해되더라도 데이터베이스·파일서버·원격접속 경로로 확산되지 않도록 하는 것이 이 설계의 목적입니다.

### 3-4. WAF/IPS 보호 대상 포함

경계에 WAF/IPS가 적용되어 있는 것으로 확인했습니다. 신규 DMZ 서버도 보호 대상에 포함해 주시기를 요청드립니다.

### 3-5. 인증서 자동 갱신을 위한 DNS 위임

외부 공개용으로 Let's Encrypt 공인 인증서를 사용할 계획이며, DNS-01 방식으로 발급합니다. 이 방식은 **발급·갱신 시마다** 아래 TXT 레코드가 필요합니다.

```
_acme-challenge.gsai.tta.or.kr    TXT    (매번 값이 바뀜)
```

인증서 유효기간이 90일이라 60일마다 갱신이 발생합니다. 매번 수동 등록을 요청드리는 것은 양쪽 모두 부담이고, 한 번 놓치면 인증서 만료로 서비스가 중단됩니다. 아래 중 하나로 처리해 주시면 자동화가 가능합니다.

1. **(권장)** `_acme-challenge.gsai.tta.or.kr` 를 저희가 관리하는 이름으로 **CNAME 위임** — 1회 설정으로 이후 자동
2. 해당 레코드에 대한 DNS API 접근 권한 부여
3. 위 두 가지가 불가하다면, 갱신 시점마다 수동 등록 요청 (60일 주기)

어느 방식이 가능한지 알려주시면 그에 맞춰 준비하겠습니다.

### 3-6. DMZ 서버 관리 접근 경로

3-3의 5번(내부 → DMZ 차단)을 적용하면 사내에서 DMZ 서버로 직접 접속할 수 없습니다. OS 패치와 설정 변경을 위한 관리 경로가 필요합니다.

기존에 운용 중인 관리망이나 점프박스가 있다면 그 경로를 사용하겠습니다. 표준 방식이 어떻게 되는지 안내를 부탁드립니다.

## 5. 저희 측 보안 조치 (참고)

외부 공개에 앞서 앱 측에서 아래를 적용할 예정입니다.

- 전 기능 로그인 필수화 (구글 계정 미로그인 시 접근 불가), 회사 계정 여부 서버 검증
- 관리자 페이지 및 사내 전용 API는 외부 경로에서 차단
- 접속·감사 로그 기록 (로그인, 산출물 다운로드, 판정 변경 이력)
- 요청 속도 제한 및 로그인 실패 반복 IP 자동 차단
- 업로드 용량 제한
- DMZ 서버에는 애플리케이션·데이터베이스·계정 정보 미보유
- 앱 서버의 불필요한 외부 노출 포트 정리
