# test.zip ECM Flow Simulation

## 목적

`C:\Users\jh910\Documents\New project 2\test.zip`의 압축 내부 구조가 ECM 좌측 트리의 실제 폴더/파일 구조와 동일하다고 가정하고, 다운로드부터 점검까지 어떤 흐름으로 동작해야 하는지 시뮬레이션한다.

이 문서는 하위 폴더 반복 다운로드 기능 구현 전에 기준 시나리오로 사용한다.

## 기존 다운로드 방식으로 보면

현재 구현은 프로젝트 폴더를 찾은 뒤 해당 폴더의 우측 문서 목록을 전체 선택하고 다운로드한다.

```text
프로젝트 폴더 선택
  -> 우측 목록 전체 선택
  -> 다운로드 1회
  -> 다운로드 완료 후 점검
```

이 방식이 ECM에서 하위 폴더 내부 파일까지 자동으로 내려주지 않는다면, `test.zip` 구조에서는 최상위의 `2.계약`, `4.시험`, `5.인증관련`, `6.홍보자료` 폴더만 보이고 실제 내부 파일 530개가 누락될 수 있다.

따라서 이 샘플 구조는 새 요구사항인 “좌측 트리 하위 폴더 반복 탐색/다운로드”가 필요한 케이스다.

## 새 다운로드 방식 시뮬레이션

### 1. ECM 프로젝트 폴더 진입

센터별 기존 트리 규칙에 따라 프로젝트 폴더까지 진입한다.

예: 상암 기준

```text
상암AX센터
  > 2026년 시험서비스
    > 01 GS인증시험(1등급)
      > TTA-26-00266 포함 프로젝트 폴더
```

### 2. 프로젝트 폴더 아래 depth-first 탐색

프로젝트 폴더를 루트로 보고 좌측 트리를 깊이 우선으로 탐색한다.

```text
TTA-26-00266
  > 2.계약
  > 4.시험
    > 가.계획
    > 나.설계
      > 제품 스크린샷
        > 패치 전
        > 패치 후
    > 다.수행
      > 결함 스크린샷
        > 1차 결함
          > 1차-01...
          > ...
        > 2차 결함
          > 2차-01...
          > ...
      > 보안성시험
        > 패치전
        > 패치후
      > 성능시험
        > rawdata v1.0
          > 패치전
          > 패치후
    > 라.종료
  > 5.인증관련
  > 6.홍보자료
```

## 전체 흐름 시뮬레이션

```text
1. 작업 생성
   - 프로젝트번호: TTA-26-00266
   - center_code: sangam/yeongnam/bundang 중 실제 센터

2. worker 시작
   - 해당 서버의 ECM URL 접속
   - 센터 루트 폴더 선택
   - 2026년 시험서비스 선택
   - 센터별 시험유형 폴더 선택
   - 프로젝트번호 포함 폴더 선택

3. 하위 폴더 반복 다운로드
   - 프로젝트 폴더 아래 tree를 depth-first로 순회
   - 우측 문서 목록 파일 수가 1개 이상이면 전체 선택
   - 다운로드 메뉴 실행
   - 같은 로컬 프로젝트 폴더를 대상 폴더로 선택
   - 전송 완료 대기
   - 다음 폴더로 이동

4. 다운로드 검증
   - 로컬 프로젝트 폴더 존재 확인
   - 총 파일 수 530개 기대
   - 0바이트 파일 없음 확인
   - 필요한 경우 ECM별 문서 수 합계와 로컬 파일 수 비교

5. 점검 실행
   - 로컬 프로젝트 폴더 전체 스캔
   - 파일 530개, 폴더 36개 기준으로 18개 규칙 검사
   - 규칙별 결과 저장

   - 점검결과: 부적합
```

## 구현 때 특히 조심할 부분

1. 파일이 없는 중간 폴더를 실패로 처리하면 안 된다.
   - 예: `4.시험`, `제품 스크린샷`, `결함 스크린샷`, `1차 결함`, `2차 결함`, `rawdata v1.0`

2. 폴더 선택 후 우측 문서 목록이 이전 폴더 내용으로 남아 있을 수 있다.
   - 선택한 좌측 트리 노드와 우측 목록 갱신 완료 조건을 같이 확인해야 한다.

3. 다운로드를 29회 실행하므로 ECM agent 팝업/전송현황 대기가 반복 가능해야 한다.
   - 첫 다운로드 후에도 다음 다운로드 메뉴 클릭이 정상 동작하는지 확인해야 한다.

4. 같은 로컬 프로젝트 폴더를 반복 선택해야 한다.
   - 하위 폴더마다 다른 로컬 폴더를 만들면 최종 구조가 깨진다.

5. ECM agent가 경로를 자동 재현하지 않으면 추가 설계가 필요하다.
   - 예: `패치 전` 폴더를 다운로드했는데 로컬에서 `4.시험/나.설계/제품 스크린샷/패치 전` 구조가 만들어지지 않는 경우

6. 문서가 많은 폴더는 전송 대기 시간이 길 수 있다.
   - `패치 후` 폴더는 273개 파일이 있어 timeout 조정이 필요할 수 있다.
