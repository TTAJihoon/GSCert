# ECM 파일 다운로드 캐시 검토

## 목적

기존 시험 이력 조회와 유사 시험 조회 페이지의 ECM 버튼은 ECM에서 파일 URL을 복사해 사용자 브라우저에서 열도록 동작한다.
이 문서는 해당 흐름을 서버 파일 다운로드 캐시 방식으로 바꿀 때의 방향과 주의점을 보관한다.

## 현재 동작

- 대상 화면:
  - `/history/`
  - `/similar/`
- 버튼 클릭 시 JavaScript가 `인증일자`, `시험번호`를 추출한다.
- WebSocket `/ws/run_job/`으로 요청한다.
- 서버는 `main/data/ecmURL.db`에서 `시험번호 -> URL` 캐시를 먼저 조회한다.
- 캐시가 있으면 ECM 자동화를 실행하지 않고 URL을 바로 반환한다.
- 캐시가 없으면 Playwright가 ECM에 접속해 해당 인증일자/시험번호 위치로 이동한다.
- 현재 자동화는 시험성적서 항목을 찾고 체크박스를 선택한 뒤 URL 복사 버튼을 눌러 URL을 얻는다.
- 얻은 URL은 `ecmURL.db`에 저장하고, 사용자 브라우저는 반환된 URL을 새 탭으로 연다.

관련 파일:

- `playwright_job/consumers.py`
- `playwright_job/tasks.py`
- `playwright_job/ecm.py`
- `main/static/scripts/testing/history_ECM.js`
- `main/static/scripts/testing/similar_ecm.js`

## 변경 목표

- 캐시 키는 기존처럼 `시험번호`를 사용한다.
- 저장 폴더는 하나로 통일한다.
- 다운로드 대상은 시험성적서 1개다.
- ECM에서 해당 시험성적서 항목 체크박스를 선택하고 URL 복사가 아니라 실제 파일 다운로드를 수행한다.
- 다운로드된 시험성적서는 서버에 영구 보관한다.
- 다음 요청부터는 ECM 자동화를 실행하지 않고 서버에 저장된 파일을 사용자 브라우저로 다운로드하게 한다.

## 추천 구조

기존 `ecmURL.db`를 덮어쓰기보다 파일 캐시 전용 테이블 또는 DB를 따로 둔다.

추천 테이블 예시:

```sql
CREATE TABLE IF NOT EXISTS ecm_file_cache (
    test_no TEXT PRIMARY KEY,
    filename TEXT NOT NULL,
    relative_path TEXT NOT NULL,
    file_size INTEGER DEFAULT 0,
    downloaded_at TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'available'
);
```

권장 흐름:

1. 사용자가 ECM 다운로드 버튼을 클릭한다.
2. 서버가 `시험번호`로 파일 캐시 DB를 조회한다.
3. DB row가 있고 실제 파일도 존재하면 서버 내부 다운로드 URL을 반환한다.
4. DB row가 없거나 실제 파일이 없으면 ECM 자동화를 실행한다.
5. ECM에서 시험성적서 체크박스를 선택하고 파일 다운로드를 수행한다.
6. 다운로드 완료 후 파일명, 상대경로, 크기, 다운로드 시각을 DB에 저장한다.
7. 사용자 브라우저는 서버 다운로드 API를 통해 파일을 받는다.

기존 JS는 성공 응답의 `url`을 열고 있으므로, 서버가 ECM 외부 URL 대신 예를 들어 `/api/ecm-files/{test_no}/download/` 같은 내부 URL을 반환하면 UI 변경을 최소화할 수 있다.

## 주의할 문제

### DB와 실제 파일 불일치

DB에는 있는데 실제 파일이 없을 수 있다.
이 경우 캐시 miss로 보고 ECM에서 다시 다운로드하는 것이 좋다.

반대로 실제 파일은 있는데 DB가 없으면 운영상 꼬인 상태로 본다.
자동 등록보다 관리자 로그를 남기고 새로 다운로드하는 쪽이 안전하다.

### 부분 다운로드 파일

다운로드 실패 후 일부 파일이 남을 수 있다.
실패 시 임시 파일 또는 불완전한 결과 파일은 삭제해야 한다.
그렇지 않으면 다음 요청에서 깨진 파일을 정상 캐시로 오인할 수 있다.

### 파일명 충돌

저장 폴더를 하나로 통일하기 때문에 파일명 충돌 가능성이 있다.
추천 파일명은 `{시험번호}_{원본파일명}`이다.

### ECM 세션과 다운로드 방식

ECM URL을 `requests`나 `httpx`로 바로 다운로드할 수 있으면 구현이 단순하다.
세션 쿠키가 필요하거나 Windows agent 다운로드 흐름이 필요하면 Playwright context 다운로드 또는 기존 agent 팝업 자동화 흐름을 재사용해야 한다.

### 보안

사용자에게 서버 절대경로를 노출하지 않는다.
다운로드 API는 반드시 서버가 관리하는 캐시 폴더 내부 파일만 반환해야 하며, path traversal 방어가 필요하다.

## 현재 결정

- 키: `시험번호`
- 저장 폴더: 단일 폴더
- 대상 파일: 시험성적서 1개
- 캐시 파일 보관: 영구 보관
- 수동 재다운로드 버튼: 1차 구현에서는 만들지 않는다.

수동 재다운로드 버튼은 이미 저장된 파일이 있어도 사용자가 캐시를 무시하고 ECM에서 다시 받아오게 하는 기능이다.
현재 요구사항에서는 없어도 된다.

## 남은 결정

1. 단일 저장 폴더의 실제 위치
   - 추천: `ECM_FILE_CACHE_DIR` 설정값으로 분리한다.
   - 이유: 운영 서버에서 데이터 디스크나 백업 대상 폴더로 옮기기 쉽다.
2. 파일 다운로드 API URL 형태
   - 추천: `/api/ecm-files/<str:test_no>/download/`
   - 이유: 기존 JS가 `url`을 열기만 하면 되므로 화면 변경을 줄일 수 있다.
3. 기존 URL 캐시 유지 여부
   - 추천: 기존 URL 캐시는 그대로 두고 파일 캐시는 별도로 추가한다.
   - 이유: 기존 기능 회귀 위험을 줄이고, 필요하면 단계적으로 전환할 수 있다.
