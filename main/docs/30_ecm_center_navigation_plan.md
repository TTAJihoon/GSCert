# ECM Center Navigation Plan

## 목적

센터별 ECM 접속 IP, 앱 서버 배치, ECM 폴더 트리 탐색 규칙, 하위 폴더가 있는 프로젝트 폴더 다운로드 방식을 구현 전에 고정한다.

이 문서는 `ecm_download.py`, `ecm_download_review_centers.py`, worker 다운로드 로직을 수정할 때마다 먼저 확인한다.

## 용어 구분

| 용어 | 의미 |
| --- | --- |
| 앱 서버 IP | `/download-review/` Django 화면과 worker가 실행되는 서버 IP |
| ECM 접속 IP | Playwright가 접속하는 실제 ECM 웹 주소 |
| 센터 루트 폴더 | ECM 좌측 트리의 `상암AX센터`, `영남AX센터`. 분당은 센터 루트 없이 연도 시험서비스 폴더부터 시작 |
| 시험서비스 폴더 | 프로젝트번호의 연도에서 계산한 `{year}년 시험서비스` 폴더 |
| 시험유형 폴더 | `01 GS인증시험(1등급)` 또는 `03 GS 시험인증(1등급)` 같은 하위 분류 폴더 |
| 프로젝트 폴더 | 폴더명에 프로젝트번호가 포함된 최종 프로젝트 루트 폴더 |
| 문서 목록 | 우측 목록에서 체크박스를 선택하고 다운로드하는 파일/폴더 목록 |

## 서버와 ECM 접속

| 센터 | center_code | 앱 서버 | ECM 접속 IP/URL | Playwright 실행 위치 | 상태 |
| --- | --- | --- | --- | --- | --- |
| 상암 | `sangam` | `210.96.71.241` | 현재 상암 ECM 접속 URL. 코드 기본값은 `http://210.96.71.85` | `210.96.71.241` | 완성 기준선 |
| 영남 | `yeongnam` | `210.96.71.241` | 상암과 동일 | `210.96.71.241` | 다음 구현 대상 |
| 분당 | `bundang` | `210.96.71.194` | `http://210.104.181.10` | `210.96.71.194` | 이후 구현 대상 |

주의:

- `210.96.71.194`, `210.96.71.241`은 앱 서버 IP다.
- `210.104.181.10`은 분당 ECM 접속 IP다.
- 영남은 상암과 동일한 ECM 접속 IP/URL과 동일한 앱 서버에서 Playwright를 실행한다.
- 분당은 ECM 접속 IP만 다르고, 페이지 기능/selector/다운로드 메뉴 흐름은 상암과 동일하다고 본다.

## 센터별 기본 트리 경로

### 상암

상암은 완성 기준선이다.

```text
상암AX센터
  > {year}년 시험서비스
    > 01 GS인증시험(1등급)
      > {프로젝트번호 포함 폴더}
```

### 영남

영남은 상암과 같은 ECM 접속 IP, 같은 앱 서버, 같은 폴더 구조를 사용한다. 시작 루트만 `영남AX센터`로 바뀐다.

```text
영남AX센터
  > {year}년 시험서비스
    > 01 GS인증시험(1등급)
      > {프로젝트번호 포함 폴더}
```

구현 포인트:

- `center_code=yeongnam`일 때 루트 폴더만 `영남AX센터`로 선택한다.
- 시험서비스 폴더, 시험유형 폴더, 프로젝트 폴더 탐색 방식은 상암과 동일하게 유지한다.
- 상암/영남이 같은 서버에서 동작하므로 `ECM_BASE_URL`은 하나를 공유해도 된다.

### 분당

분당은 ECM 접속 IP가 다르고, 실제 접속 계정 기준으로 센터 루트 폴더 없이 연도 시험서비스 폴더부터 시작한다.

```text
{year}년 시험서비스
  > 03 GS 시험인증(1등급)
    > {프로젝트번호 포함 폴더}
```

구현 포인트:

- `center_code=bundang`일 때 Playwright 접속 URL은 `http://210.104.181.10`이어야 한다.
- `center_code=bundang`일 때 `상암AX센터`/`영남AX센터` 같은 센터 루트 탐색 단계를 건너뛴다.
- 시험유형 폴더는 정확한 전체 문자열에 묶지 말고 `GS 시험인증(1등급)` 포함 조건으로 찾는다.
- `03 GS 시험인증(1등급)`처럼 앞 번호가 바뀌어도 동작해야 한다.

## 현재 탐색 로직

현재 `ecm_download.py`의 큰 흐름은 다음과 같다.

```text
1. ECM_BASE_URL 접속
2. 좌측 트리(`#edm-folder`) 로딩 대기
3. 프로젝트번호에서 연도 추출
   예: TTA-26-00009 -> 2026
4. 센터 루트 폴더 펼침
5. `{year}년 시험서비스` 폴더 펼침/클릭
6. 시험유형 폴더 펼침/클릭
7. 프로젝트번호가 포함된 프로젝트 폴더 클릭
8. 우측 문서 목록에서 전체 선택
9. 고급 메뉴 > 파일 다운로드 클릭
10. Windows 폴더 선택/전송현황 처리로 이동
```

현재 한계:

- 시험유형 폴더가 `01 GS인증시험(1등급)` 하나의 상수로 고정되어 있다.
- 프로젝트 폴더를 찾은 뒤 우측 목록만 전체 선택한다.
- 프로젝트 폴더 아래 하위 폴더가 트리 구조로 더 존재하는 경우, 하위 폴더별 문서 목록을 반복 다운로드하지 않는다.

## 하위 폴더 반복 다운로드 요구사항

기존 방식:

```text
프로젝트 폴더 선택
  -> 우측 목록 전체 선택
  -> 다운로드 1회
```

새 요구사항:

```text
프로젝트 폴더 A 선택
  -> A의 우측 목록에 파일이 있으면 다운로드
  -> 좌측 트리에서 A 아래 하위 폴더 AA, AB, AC 확인
  -> AA 선택 후 우측 목록 다운로드
  -> AB 선택 후 우측 목록 다운로드
  -> AC 선택 후 우측 목록 다운로드
  -> 더 깊은 하위 폴더가 있으면 동일하게 반복
```

다운로드 결과 기대:

```text
로컬 다운로드 폴더/
  A/
    A 폴더의 파일 1개
    AA/
      AA 폴더의 파일들
    AB/
      AB 폴더의 파일들
    AC/
      AC 폴더의 파일들
```

## 다운로드 팝업 제어 공식

ECM에서 프로젝트번호가 포함된 폴더를 찾으면 그 폴더를 다운로드 root로 본다.
프로젝트 root 아래에서 파일이 있는 폴더를 다운로드할 때마다 ECM root부터 현재 폴더까지의 상대 경로를 기억하고,
로컬 다운로드 기준 폴더 아래에도 같은 폴더 구조를 만든다.

예시:

```text
ECM: TTA-26-00195 > 2.계약
로컬: {다운로드 기준 폴더} > TTA-26-00195 > 2.계약
```

더 깊은 예시:

```text
ECM: TTA-26-00195 > 4.시험 > 성능시험 > A폴더
로컬: {다운로드 기준 폴더} > TTA-26-00195 > 4.시험 > 성능시험 > A폴더
```

분당 서버에서 다운로드 기준 폴더로 처음 이동하는 키 입력은 다음과 같다.

```text
Shift+Tab 2회
PageUp
아래 방향키 3회
오른쪽 방향키 1회
아래 방향키 2회
오른쪽 방향키 1회
```

그 뒤 현재 ECM 상대경로의 각 폴더명마다 다음을 반복한다.

```text
Alt+M
1초 대기
폴더명 입력
Enter
```

마지막 폴더까지 준비되면 `Enter`로 다운로드를 시작한다.

이미 프로젝트 폴더가 만들어져 있는 경우에는 새 이름을 붙이지 않는다.
다음 순서로 다운로드 기준 폴더까지 복귀한 뒤 기존 프로젝트 폴더와 이미 만든 하위 폴더를 찾아 들어가고,
아직 없는 하위 폴더만 새로 만든다.

```text
왼쪽 방향키 12회
오른쪽 방향키 1회
아래 방향키 3회
오른쪽 방향키 1회
아래 방향키 2회
오른쪽 방향키 1회
```

상암/영남은 추후 별도 기준 폴더 이동 공식을 받으면 서버별로 추가한다.
다운로드 기준 폴더에 도착한 뒤 `프로젝트번호/상대경로`를 만들거나 기존 폴더로 들어가는 방식은 센터 공통으로 사용한다.

핵심 판단:

- ECM이 현재 선택한 좌측 트리 폴더 기준으로 다운로드 경로를 재현해 주는지 확인해야 한다.
- 같은 프로젝트 폴더 안에서 하위 폴더별 다운로드를 여러 번 실행했을 때, 기존 다운로드 폴더에 누적 저장되는지 확인해야 한다.
- 하위 폴더를 다운로드할 때마다 같은 로컬 프로젝트 폴더를 선택해야 한다.

## 구현 설계 초안

### 1. 센터별 ECM 접속 URL

현재 `_ecm_url()`은 전역 `ECM_BASE_URL`만 본다. 센터별로 다음 중 하나를 선택한다.

추천:

```text
ECM_BASE_URL_SANGAM = http://상암/영남 ECM
ECM_BASE_URL_YEONGNAM = http://상암/영남 ECM
ECM_BASE_URL_BUNDANG = http://210.104.181.10
```

그리고 `run_ecm_automation(..., center_code=...)`에서 센터별 URL을 선택한다.

서버별 환경변수 운영도 가능하다.

```text
241 서버: ECM_BASE_URL=http://상암/영남 ECM
194 서버: ECM_BASE_URL=http://210.104.181.10
```

다만 구현 실수를 줄이려면 센터별 URL 설정 이름을 명시적으로 두는 편이 더 좋다.

### 2. 센터별 시험유형 폴더 매칭

현재 상수:

```text
ECM_TREE_TEST_TYPE = "01 GS인증시험(1등급)"
```

추천 구조:

```text
sangam:
  exact: 01 GS인증시험(1등급)
yeongnam:
  exact: 01 GS인증시험(1등급)
bundang:
  contains: GS 시험인증(1등급)
```

구현 시 `exact` 먼저, 없으면 `contains`를 적용하거나 센터별 match mode를 둔다.

### 3. 프로젝트 폴더 하위 탐색

프로젝트 폴더를 찾은 뒤, 좌측 tree의 해당 `li`를 기준으로 depth-first traversal을 수행한다.

권장 순서:

```text
1. 프로젝트 폴더 노드 선택
2. 해당 노드의 문서 목록 다운로드
3. 프로젝트 폴더 노드 펼침
4. 직접 하위 폴더 목록 수집
5. 각 하위 폴더에 대해:
   5-1. 폴더 선택
   5-2. 문서 목록 다운로드
   5-3. 하위 폴더가 있으면 재귀 반복
```

주의:

- 같은 폴더를 중복 방문하지 않도록 ECM tree node id 또는 전체 트리 경로를 visited key로 둔다.
- 폴더 선택 후 문서 목록이 이전 폴더의 목록으로 남아 있을 수 있으므로, 선택 노드 텍스트 또는 목록 refresh 완료 조건을 확인해야 한다.
- 문서 목록이 비어 있어도 하위 폴더가 있을 수 있으므로, `문서 0개`를 곧바로 실패로 보면 안 된다.
- 전체 프로젝트에서 파일이 하나도 없고 하위 폴더에도 파일이 없을 때만 실패 처리한다.

### 4. 다운로드 대상 폴더 선택

하위 폴더별로 다운로드 메뉴를 여러 번 실행할 수 있으므로, agent popup 쪽은 같은 로컬 프로젝트 폴더를 반복 선택할 수 있어야 한다.

확인할 내용:

- 최초 다운로드 때 만든 로컬 프로젝트 폴더를 다음 하위 폴더 다운로드에도 재사용하는지
- 이미 같은 파일이 있으면 ECM agent가 덮어쓰기/중복 알림을 띄우는지
- 중복 알림 처리 후에도 다음 하위 폴더 다운로드가 이어지는지

## 테스트 계획

### 1. 상암 회귀 테스트

목적: 완성된 상암 로직이 깨지지 않았는지 확인한다.

테스트 조건:

- 서버: `210.96.71.241`
- center: `sangam`
- 샘플: 기존에 성공한 상암 프로젝트번호

확인:

- 상암 ECM URL 접속 성공
- `상암AX센터` 선택
- `{year}년 시험서비스` 선택
- `01 GS인증시험(1등급)` 선택
- 프로젝트 폴더 선택
- 기존 방식 다운로드 성공
- 기존 산출물 점검 결과 변화 없음

### 2. 영남 트리 테스트

목적: 상암과 같은 서버/같은 ECM URL에서 루트만 영남으로 바꿔 정상 탐색되는지 확인한다.

테스트 조건:

- 서버: `210.96.71.241`
- center: `yeongnam`
- 샘플: 영남 프로젝트번호 1개

확인:

- 상암과 같은 ECM URL 접속 성공
- `영남AX센터` 선택
- `{year}년 시험서비스` 선택
- `01 GS인증시험(1등급)` 선택
- 프로젝트 폴더 선택
- 문서 목록 표시
- 다운로드 성공

### 3. 분당 접속/트리 테스트

목적: 다른 ECM IP와 다른 시험유형 폴더명을 처리하는지 확인한다.

테스트 조건:

- 서버: `210.96.71.194`
- center: `bundang`
- ECM URL: `http://210.104.181.10`
- 샘플: 분당 프로젝트번호 1개

확인:

- 분당 ECM URL 접속 성공
- `분당AX센터` 선택
- `{year}년 시험서비스` 또는 실제 표시명 선택
- `GS 시험인증(1등급)` 포함 폴더 선택
- 프로젝트 폴더 선택
- 문서 목록 표시
- 다운로드 성공

### 4. 하위 폴더 반복 다운로드 단위 테스트

목적: tree traversal 로직이 폴더를 빠뜨리지 않고 순회하는지 확인한다.

실제 ECM 없이 테스트할 수 있는 항목:

- 프로젝트 폴더 노드 아래 직접 하위 폴더 목록 추출
- 하위 폴더 depth-first 방문 순서
- visited 처리로 중복 방문 방지
- 파일 0개 폴더가 있어도 하위 폴더 방문 유지

예상 방문 순서:

```text
A
A/AA
A/AB
A/AC
```

### 5. 하위 폴더 반복 다운로드 실제 ECM 테스트

목적: 실제 ECM agent 다운로드 결과가 기대 로컬 구조와 일치하는지 확인한다.

테스트 조건:

```text
프로젝트 폴더 A
  - A 폴더 문서 1개
  - AA 폴더 문서 N개
  - AB 폴더 문서 N개
  - AC 폴더 문서 N개
```

확인:

- A 폴더 문서가 로컬 A 폴더 바로 아래에 저장되는지
- AA/AB/AC 문서가 각각 로컬 하위 폴더 아래에 저장되는지
- 다운로드가 여러 번 실행되어도 이전 결과가 사라지지 않는지
- 중복 파일 알림이 뜨면 자동 처리되는지
- 최종 파일 수가 ECM 화면의 각 폴더 문서 수 합계와 일치하는지

### 6. 실패/예외 테스트

확인할 실패 케이스:

- 프로젝트 폴더는 있지만 모든 폴더 문서 수가 0개
- 프로젝트 폴더 아래 하위 폴더는 있지만 권한 문제로 문서 목록이 안 뜸
- 하위 폴더 클릭 후 이전 문서 목록이 그대로 남아 있는 상황
- ECM agent 전송현황이 완료되지 않는 상황
- 중복 파일 시스템 알림이 반복 발생하는 상황

기대 처리:

- 특정 하위 폴더 실패는 전체 실패로 볼지, 해당 폴더만 실패 로그로 남기고 다음 폴더를 계속할지 결정 필요
- 다운로드 성공/실패 로그에는 센터, 프로젝트번호, ECM 트리 경로, 문서 수를 남긴다.

## 구현 시 결정 필요

1. 하위 폴더 중 하나가 다운로드 실패하면 전체 프로젝트를 실패로 볼지, 일부 실패로 보고 다음 하위 폴더를 계속할지 결정한다.
2. 문서가 없는 폴더가 있을 때 로그만 남길지, 사용자에게 표시할지 결정한다.
3. 하위 폴더 반복 다운로드 시 ECM agent가 로컬 폴더 구조를 자동 재현하지 않는 경우, 로컬에서 폴더를 직접 만들고 폴더별 다운로드 위치를 바꿀 수 있는지 확인해야 한다.
4. 분당 시험서비스 폴더명이 `2026 시험서비스`인지 `2026년 시험서비스`인지 실제 화면 기준으로 확정한다.
5. 상암 ECM 접속 URL을 명시 환경변수로 고정할지, 현재 `ECM_BASE_URL` 값을 유지할지 결정한다.
